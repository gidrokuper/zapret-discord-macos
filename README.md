# zapret для Discord на macOS

Набор скриптов, чтобы Discord на Mac работал в обход DPI-блокировки провайдера.
Внутри [zapret](https://github.com/bol-van/zapret) от bol-van: из него собран только `tpws`, универсальный бинарник для Apple Silicon и Intel.

- Не нужен ни VPN, ни сторонний сервер: трафик идёт напрямую в Discord.
- Не нужен `sudo`, и системные настройки сети не меняются.
- Обход работает только для Discord, остальной трафик не затрагивается.

## Быстрый старт

1. Скачай репозиторий: кнопка **Code → Download ZIP** или
   ```bash
   git clone https://github.com/gidrokuper/zapret-discord-macos.git ~/zapret-discord-macos
   ```
2. Запусти:
   ```bash
   ~/zapret-discord-macos/discord.sh
   ```
   Скрипт поднимет обход и перезапустит Discord через него.
3. Чтобы выключить обход:
   ```bash
   ~/zapret-discord-macos/stop.sh
   ```

Если macOS ругается на `tpws` (*«не удалось проверить разработчика»*), выполни один раз:
```bash
xattr -d com.apple.quarantine ~/zapret-discord-macos/tpws
```
`start.sh` делает это сам, но для архива из ZIP может понадобиться вручную.

После перезагрузки Mac обход нужно запустить снова через `discord.sh`.

## Если не работает: смени стратегию

У разных провайдеров разный DPI, поэтому есть 4 стратегии обхода. Перебирай, пока Discord не загрузится:

```bash
~/zapret-discord-macos/stop.sh && ~/zapret-discord-macos/discord.sh 2
```

| № | Параметры tpws | Идея |
|---|---|---|
| 1 | `--split-pos=1,midsld --disorder --tlsrec=sniext` | по умолчанию, самая универсальная |
| 2 | `--split-pos=1,midsld --disorder` | без разбиения TLS-записи |
| 3 | `--split-pos=1,sniext+1 --disorder --tlsrec=sniext` | разрез внутри SNI |
| 4 | `--split-pos=2 --tlsrec=sniext` | без disorder, мягкий вариант |

Проверка, что прокси жив и Discord через него отвечает:
```bash
~/zapret-discord-macos/start.sh && ~/zapret-discord-macos/check.sh
```

## Как это работает

```
Discord ──socks5──▶ tpws (127.0.0.1:1080) ──TCP, порезанный ClientHello──▶ серверы Discord
                         ▲
                 DPI провайдера не может
                 прочитать имя сайта (SNI)
```

1. **Как блокирует провайдер.** При HTTPS-соединении браузер или приложение первым пакетом шлёт TLS ClientHello, а в нём открытым текстом указано имя сайта (SNI), например `discord.com`. DPI-оборудование провайдера читает SNI и, увидев запрещённый домен, рвёт соединение.

2. **Что делает tpws.** Это локальный прокси. Discord отдаёт ему соединения, а tpws открывает их к серверу сам и при отправке ClientHello «портит» его так, чтобы DPI не смог прочитать имя, а сервер всё понял:
   - `--split-pos` режет ClientHello на несколько TCP-сегментов (например, посреди домена: `disc` + `ord.com`). Простой DPI анализирует только первый пакет и не видит имени целиком.
   - `--disorder` отправляет сегменты в обратном порядке. Сервер собирает их правильно по TCP, а DPI, не собирающий поток, сбивается.
   - `--tlsrec=sniext` делит сообщение на две TLS-записи. Это корректно по стандарту TLS, но многие DPI такое не разбирают.

   Шифрование при этом не ломается и не подменяется: tpws не видит содержимое переписки, он только по-другому нарезает уже зашифрованный поток.

3. **Только Discord.** В [`discord.txt`](discord.txt) перечислены домены Discord. Трюки применяются только к ним (с поддоменами), остальное проходит через прокси как есть.

4. **Как Discord попадает в прокси.** Discord построен на Chromium, поэтому понимает флаг `--proxy-server`. `discord.sh` закрывает Discord и запускает его заново с флагом `--proxy-server=socks5://127.0.0.1:1080`. При SOCKS5 имена доменов резолвит сам tpws, так что подмена DNS у провайдера тоже не мешает.

## Файлы

| Файл | Что делает |
|---|---|
| `discord.sh [N]` | поднимает tpws (если не запущен) и перезапускает Discord через него |
| `start.sh [N]` | запускает только tpws со стратегией N (1–4) |
| `stop.sh` | останавливает tpws |
| `check.sh` | сравнивает доступ к Discord напрямую и через tpws |
| `discord.txt` | список доменов, к которым применяется обход |
| `tpws` | бинарник из zapret (arm64 + x86_64) |

## Ограничения

- **Голосовые каналы и звонки могут не работать.** Голос Discord идёт по UDP, а tpws на macOS умеет только TCP. Чат, сервера, картинки, файлы и обновления работают.
- Сейчас Discord нужно запускать через `discord.sh`. Если открыть его обычным способом, он пойдёт без обхода.
- **Браузер.** Чтобы открыть discord.com в браузере, укажи в его настройках прокси SOCKS5 `127.0.0.1:1080`. Также можно запустить Chrome с `--proxy-server="socks5://127.0.0.1:1080"`.

## Собрать tpws самому

Если не хочешь доверять готовому бинарнику, собери его сам (нужны Xcode Command Line Tools):

```bash
git clone --depth 1 https://github.com/bol-van/zapret.git
cd zapret && make mac
cp binaries/my/tpws ~/zapret-discord-macos/tpws
```

Бинарник в репозитории собран именно так, из коммита `73ee2aa` (4 ноября 2026).
